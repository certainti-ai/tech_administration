Methodology & scope

Tasks only · no state-level forms for US or Canada historical submissions · Canada keeps its original calculation logic · progress follows Migration Status, not Jira's Done category · refreshed twice daily.

This report tracks the migration of historical R&D tax-credit submissions onto the platform. One task per customer / jurisdiction / fiscal year combination. Read the scope decisions below before drawing conclusions from the numbers — some jurisdictions are deliberately migrating less than a full submission.

▲USA State-level forms excluded

State-level forms were never produced for the US, so no state-level forms will be generated for any historical submission.

The Finance team is building the requirements for state-level forms. Those will apply only to future submissions, once development is complete.

▲Canada Forms and logic both excluded

State-level forms were never produced for Canada either, so no state-level forms will be generated for any historical submission.

Finance has additionally revised the financial calculation logic itself for Canada. That revised logic will not be applied to historical submissions — they keep the logic they were originally filed under.

What counts as progress

Migration Status is the field of record and drives every number here.

Jira's own status categories can disagree with it: a column mapped to Jira's green Done category counts as done in any stock Jira progress bar even while the migration is still open. Where the two differ, this report follows Migration Status.

How to read this

Scope is Tasks only, as briefed — 44 of the project's 111 issues. The other 67 (36 Bugs, 20 Subtasks) are excluded, so defect load does not appear here.

Two different notions of "done" are live in this project. Migration Status reports 1 task Completed. Jira's own status categories, however, map the Prod Forms Validation column to the green Done category, so any stock Jira progress bar will read 23 of 44 complete. This dashboard follows Migration Status throughout, since that is the field the team maintains.

Migration Status is treated as ordered — business requirements → data import → code fix → business validation → completed — so the palette runs pale to deep along that pipeline. Jira stores no rank between these options; the order is inferred from their names.

Latest comment is the newest comment carrying text. Where the newest comment holds only screenshots or attachments, the most recent text comment is shown instead and marked (after attachment). Mentions are flattened to plain names; images are dropped.

Every task carries Medium priority, so priority is not charted — it separates nothing. The Technical issue field is empty on all 44 and is likewise omitted.
